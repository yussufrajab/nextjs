# Security Test 4.4 — Institution Filtering in Queries

> **Test Date:** 2026-07-03
> **Tester:** Automated Security Test (Claude Code)
> **Scope:** Verify all database queries include institutionId filtering and cannot be bypassed
> **Severity Scale:** Critical > High > Medium > Low > Informational

---

## Executive Summary

**Overall Verdict: ❌ FAIL — Multiple Query Paths Lack Institution Filtering**

Of the 25+ data-querying API endpoints tested:

- **8 request-type endpoints** (promotions, confirmations, etc.) correctly filter by institution ✅
- **2 employee endpoints** (documents, certificates) correctly check institution ownership ✅
- **Employee list** correctly filters but can be overridden via query param ❌
- **5 endpoints** have NO authentication and NO institution filtering ❌
- **1 endpoint** (complaints) has NO authentication and NO institution filtering ❌
- **1 endpoint** (users) returns all institutions' data ❌

### F-05: Employee List Query Param Override (Critical)

**Description:** `GET /api/employees` accepts `?institutionId=` query param that overrides the session-based filter.

**Test Result:**

| Request | Employees | Institution | Verdict |
|---------|-----------|-------------|---------|
| No params | 200 | Own (`cmd059ion...`) | ✅ |
| `?institutionId=cmd06nn7r...` | 200 | **Other** (`cmd06nn7r...`) | ❌ |

**Root Cause:** Line 125-127 in `employees/route.ts`:
```ts
if (institutionIdFilter) {
  whereClause.institutionId = institutionIdFilter; // Overwrites auth-based filter
}
```

---

### F-06: Complaints Endpoint — NO Auth, NO Filter (Critical)

**Description:** `GET /api/complaints` accepts `userId` and `userRole` as client-supplied query params with NO authentication. Returns complaints from ALL institutions.

**Test Result:**

| Request | Auth | Records | Institutions | Verdict |
|---------|------|---------|-------------|---------|
| `?userId=<self>&userRole=HRO` | Session | 29 | Multiple | ❌ |
| `?userId=<self>&userRole=HRO` | **None** | 29 | Multiple | ❌ |
| `?userId=<self>&userRole=CSCS` | Session | 29 | Multiple | ❌ |

**Sample Data Leaked:**
```json
{
  "employeeName": "Ali Mmanga",
  "institutionName": "WIZARA YA AFYA",  // Different institution!
  "complaintType": "Kuchelewa Kupandishwa Cheo",
  "subject": "..."
}
```

**Root Cause:** No `verifyAuth()` call. Uses client-supplied `userId` and `userRole` for filtering. No institution filter applied.
